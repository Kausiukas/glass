# Carved Glass Slab: Handover

**Project:** 3D carved-glass hero for marketing.ekopolimeras.com
**Package:** `glass-slab` 1.0.0 (engine v4)
**Prepared:** 29 October 2026, for Antanas / Digital Bees

This file is the full brief for implementing the effect in your own codebase and IDE. It covers what the package contains, how to drop it in, every option, how it works inside, and what to test.

---

## 1. What it is

The hero card is drawn as a real block of glass by a WebGL2 fragment shader. Every pixel follows a ray through the slab:

1. into the front face, a letter wall or a button;
2. across the body of the glass, with absorption and internal reflections;
3. out of the back face onto your background video.

The lettering is chiselled into the front face, and the two buttons are raised glass.

The HTML stays real throughout:

- Text is selectable and indexable.
- Buttons and links are focusable and clickable.
- Screen readers read the page normally.

The engine measures that HTML and builds the carving from it. Changing the copy (including an EN/LT language switch) re-carves automatically.

Everything is framework-agnostic TypeScript, with a thin React wrapper. The only runtime dependency is the browser; React is needed only for the wrapper.

## 3. Quick start (React 18 + Vite + Tailwind v4)

1. **Copy** `src/glass/` to e.g. `src/components/glass/`.
2. **Background video.** Give it an id and keep it where it is. It must be same-origin, or served with CORS headers plus `crossOrigin="anonymous"` (see §12).
3. **Wrap the hero content** in `<GlassHero>` and mark the parts with the data attributes from §4:

   ```tsx
   import { GlassHero } from "@/components/glass/GlassHero";

   <GlassHero
     background={() => document.getElementById("bg-video") as HTMLVideoElement | null}
     options={{ thickness: 44, tool: "gouge" }}
     slabClassName="w-full max-w-[920px] px-14 py-16 rounded-[28px]"
   >
     <p data-glass-carve data-glass-small>Effortless Marketing · Pure Peace of Mind</p>
     <h1 data-glass-carve>Sit Back. Let the Waves Carry Your Marketing.</h1>
     <p>Body copy: normal HTML printed on the front face.</p>
     <a href="/signup" data-glass-button="1"><span data-glass-label>Start your journey free →</span></a>
     <a href="/login"  data-glass-button="2"><span data-glass-label>Sign in</span></a>
   </GlassHero>
   ```

4. **Stacking.** Put the video at `z-0` and the element containing `<GlassHero>` at `relative z-[2]`. The wrapper renders the canvas (`z-1`) and the host (`z-2`) inside it. A complete example is `examples/SiteHero.example.tsx`.
5. **Worker.** Vite bundles it automatically. The wrapper uses `new Worker(new URL("./relief.worker.ts", import.meta.url), { type: "module" })`, so keep `relief.worker.ts` next to `GlassHero.tsx`.
6. **Run and check** that the host element carries `data-glass="on"` in DevTools. If it says `off`, WebGL2 is unavailable and the CSS fallback is showing.

**No React / other frameworks:** see `examples/vanilla.html`. Load the engine in one of two ways:

- **Classic script:** `<script src="dist/glass-slab.iife.js">`, then `new GlassSlabLib.GlassSlab({ canvas, host, slab, mode: "overlay", background: videoEl, createWorker })`.
- **ES module:** `import { GlassSlab } from "dist/glass-slab.esm.js"`.

Pass `createWorker: () => new Worker("dist/relief.worker.js")` when served over http(s). Leave it out on `file://`, where browsers refuse workers; the carving is then built on the main thread (a short pause).

Then call `.start()`.

**Opening pages from disk (file://).** Two rules:

- **Your own video won't refract.** Browsers treat a video opened from disk as cross-origin, so WebGL may not read it. `onError` reports it, and the engine falls back to its demo sea; `vanilla.html` switches to a painted stand-in instead.
- **Everything else works.** On a real web server (or `npx serve .`) your video is read normally.

**TypeScript settings:** the sources compile with the following:

- `strict`, `isolatedModules`, `moduleResolution: "Bundler"`
- `lib: ["ES2020", "DOM", "DOM.Iterable"]`, `jsx: "react-jsx"`

## 4. Markup contract

All of these go inside the slab element (the children of `<GlassHero>`).

| Attribute | On | Effect |
|---|---|---|
| `data-glass-carve` | any text element | The text is chiselled into the glass. Its CSS colour becomes transparent; the shader draws it. |
| `data-glass-carve data-glass-small` | small lines (eyebrow, kicker) | `smallLine: "print"` frosts it legibly onto the surface. `"cut"` chisels it like the headline. |
| `data-glass-button="1"` | `<a>` / `<button>` | Raised glass button, tinted (`mainColor`). Its background, border and text are hidden; it stays clickable and focusable. |
| `data-glass-button="2"` | `<a>` / `<button>` | Raised secondary button (`secondary`: clear or frosted). |
| `data-glass-label` | element inside a button | The label frosted into the button's top. If missing, the button's own text is used. |
| *(no attribute)* | anything else | Rendered as normal HTML on top of the glass (body copy, icons, badges). |

Rules:

- **Fonts.** Text is measured per character, so `text-transform`, `letter-spacing`, wrapping and responsive font sizes all work. The font must be loaded.
  - The engine waits for `document.fonts.ready` and re-carves on every `loadingdone`.
  - For Lithuanian (ą č ę ė į š ų ū ž), load Poppins with the **latin-ext** subset. Otherwise those letters fall back to another font.
- **Button radius** is read from the button's computed `border-radius`.
- **One button per kind.** Use at most one of each kind (`"1"` and `"2"`) per slab: hover and press animate every button of that kind together.
- **Relief rebuild triggers.** The relief rebuilds by itself on text changes (MutationObserver), size changes (ResizeObserver), window resize and font loads.
  - It does **not** watch attribute or class changes. If you change a font through a class without changing the size, call `engine.rebuildRelief()`.

## 5. Layout rules (important)

**Three layers.** Keep them in this order inside one stacking context:

```
background <video>      z-index 0   (fixed, object-fit: cover)
canvas.glass-canvas     z-index 1   (fixed, inset 0, pointer-events: none; set by glass.css)
.glass-host / content   z-index 2   (relative)
```

**On `.glass-slab`, never set:**

- `transform` (the engine writes it every frame)
- `overflow: hidden`
- `filter`
- `backdrop-filter`
- `perspective`

Any of these breaks the match between the HTML and the ray-traced glass. `opacity` does not break the match, but it fades only the HTML layer, not the glass.

**Corner radius.** The slab's CSS `border-radius` must equal `options.cornerRadius` (default 28 px).

**Ancestors.** An ancestor with a `transform`, `filter` or `contain: paint` turns `position: fixed` into "fixed to that ancestor", and the canvas will be mis-sized. Keep the canvas's ancestors free of these, as `<main>` / page wrappers usually are.

**Scrolling.** The host can scroll with the page. The canvas stays fixed and follows it. When the slab is more than 200 px off-screen, the engine clears the canvas once and goes fully idle: no draws, no video uploads.

## 6. API reference

### `new GlassSlab(init)`

| Field | Type | Notes |
|---|---|---|
| `canvas` | `HTMLCanvasElement` | Fixed full-viewport canvas (class `glass-canvas`). |
| `host` | `HTMLElement` | Untransformed box that positions the slab. Receives `data-glass="on" \| "off"`. |
| `slab` | `HTMLElement` | Child of host. The engine applies `perspective() rotateX() rotateY()` to it. |
| `mode` | `"overlay" \| "full"` | **overlay** (site use): the canvas is transparent except the slab, its shadow and caustics; your video stays visible. **full**: the canvas also draws the background (the lab). Fixed per instance. |
| `options` | `Partial<GlassOptions>` | See §7. |
| `background` | `HTMLVideoElement \| HTMLImageElement \| HTMLCanvasElement \| "beach"` | What the glass refracts. `"beach"` is the procedural demo sea. |
| `backgroundFit` | `"element" \| "viewport"` | `element` (default in overlay) maps the texture onto the element's on-screen box with object-fit: cover, so refraction lines up with what is visible. |
| `createWorker` | `() => Worker` | Builds the relief off the main thread. Without it the relief is computed synchronously (~250 ms jank). |
| `onStats` | `(s: GlassStats) => void` | Called every 250 ms: `{ fps, resolution, reliefMs, live, webgl, tiltX, tiltY }`. |
| `onError` | `(msg: string) => void` | Shader, texture or relief problems. Defaults to `console.warn`. |

### Methods

| Method | Purpose |
|---|---|
| `start()` / `stop()` | Begin or stop the render loop. |
| `setOptions(partial)` | Change any option live. Relief options (§7, ✓) trigger a rebuild in the worker. |
| `getOptions()` | Current full options object (copy it into your code to freeze a look). |
| `setBackground(src, fit?)` | Switch the refraction source (e.g. when the video element is replaced). |
| `pauseBackground(bool)` | Freeze the demo beach animation. |
| `rebuildRelief()` | Force a re-carve. |
| `enableDeviceTilt()` | Phones: tilt with the device. **Must be called from a tap** (iOS permission prompt). Returns `false` if refused. |
| `renderStill({ scale, crop, margin })` | Resolves a PNG `Blob` of the current frame. `scale` 1–3; `crop` is `"slab"` (default, slab plus margin) or `"viewport"`. Transparent in overlay mode. Use it for posters, OG images and the fallback. |
| `dispose()` | Remove listeners, worker and GL objects; restore the slab's transform. |
| `ok` (property) | `false` when WebGL2 is unavailable. |

### `<GlassHero>` props

- **Content and engine props:**
  - `children`
  - `options`: changes are pushed live.
  - `background`: an element or a getter evaluated after mount.
  - `mode`: default `"overlay"`.
- **Styling:** `className` (host) and `slabClassName` (slab).
- **Callbacks:** `onStats`, `onError`, `onReady(engine)`.

Notes on the wrapper:

- It creates the engine once per mount and disposes it on unmount. This is StrictMode-safe: the double mount creates, disposes and recreates the engine.
- `GlassHero` is not exported from `index.ts`, so the ESM build stays React-free. Import it from `./GlassHero` directly.

## 9. How it works

### 9.1 Coordinate system and camera match

- Everything is in **CSS pixels**, with CSS axes: x right, y down, z toward the viewer. The slab's front face is at z = 0 and the back face at z = −thickness.
- Each frame the engine writes `transform: perspective(camera) rotateX(rx) rotateY(ry)` on the slab. The shader builds the identical camera (same perspective distance, same rotation matrix, origin at the slab centre).
- As a result, the HTML on top (body copy, button hit areas, text selection) lands exactly on the ray-traced glass.
- The canvas is sized from its own `clientWidth/Height`, not `innerWidth`. On Windows, `innerWidth` includes the scrollbar and caused a misalignment.

### 9.2 Relief (the carving)

Main thread (`relief.ts`, a few ms):

1. Removes the slab's transform for one synchronous measurement. Nothing is written to the DOM, so this is safe with React.
2. Walks `[data-glass-carve]` and button labels with a `Range` per character.
3. Rasterises anti-aliased masks:
   - cut mask
   - frosted-print mask
   - button rectangles with radius

   The masks are padded by 22 px and capped at 1.2 M texels (auto) or 1.8 M (full).

Worker (`reliefCore.ts`, pure function, ~250 ms for ~1300×570):

1. **Distance.** An exact Euclidean distance transform (Felzenszwalb–Huttenlocher) gives each pixel's distance to the letter edge. A max filter of that distance gives the local stroke half-width.
2. **Depth profile.** The depth is `D = min(maxDepth, tan(wallAngle) · halfWidth)`. The profile then depends on the tool:
   - gouge: `D·(1−(1−s)²)`, a rounded floor
   - vee: `D·s`, a crease
   - sand: a flat floor
3. **Hand-made texture.** Wobble noise, tool marks and conchoidal chips are added along the rim.
4. **Buttons.** Analytic rounded-rect SDF with pillow, dome or bevel profiles.
5. **Output textures:**
   - **RGBA16F** height field: slope x, slope y, height in CSS px, ambient occlusion.
   - **RGBA8** material map: cut weight, button id, print mask, chip mask / button u.

### 9.3 Shader (`SLAB_FS`, per pixel)

1. **Hit the slab.** Ray-march a rounded-box SDF, adaptive step plus bisection; no stepping holes on the silhouette.
2. **Front surface.** Inside the relief rectangle, a linear search (48 steps) plus bisection (7) finds the carved or raised surface between `uZTop` and `uZBot`.
3. **Normal.** Taken from the height-field slopes, plus a frost micro-normal and cut finish roughness.
4. **Reflection.** Schlick Fresnel into the environment (sky dome with procedural clouds and the scene below, or a studio softbox), plus a sun highlight.
5. **Refraction.** `refract()` at IOR 1.5. **The normal must face against the ray** (`refract(dir, -N, ior)` on exit), or the glass turns milky.
6. **Inside the glass.**
   - Beer–Lambert absorption per CSS px travelled. The slab-edge "green" boost applies only to non-relief hits; otherwise chips and button walls go dark green.
   - Up to 6 total internal reflection bounces.
   - Back-face ghost reflection of the letters.
   - Bubbles on 3 depth layers.
7. **Exit and background.** Exit through the back face, then sample the background texture at the offset implied by the 240 px gap behind the glass. Dispersion traces red and blue with separate IORs on low-bounce, smooth paths only.
8. **Light on the background.** Soft shadow plus caustics: a bevel band and a blurred Laplacian of the relief, so it is never a crisp copy of the letters.
9. **Anti-aliasing.** Silhouette pixels are flagged and re-shaded with 5 rotated-grid samples.
10. **Overlay output.** Premultiplied alpha: shadow becomes alpha, caustics become additive light, misses are transparent.

### 9.4 Render loop

The loop only draws when something changed (render on demand):

- tilt moving, button animating or host moved
- options changed or the relief arrived
- a **new video frame** (via `requestVideoFrameCallback`; otherwise on every frame while the video plays)

When nothing changes, each frame costs one `getBoundingClientRect` and a few comparisons in JS, and no GPU work.

Other behaviour:

- **Scissor.** Drawing is clipped to a box around the slab, its shadow and caustics.
- **Adaptive resolution.** In `auto`, two consecutive seconds under 30 fps step down ×0.85 (minimum 0.8). Three seconds over 55 fps step up ×1.12 (maximum 1.5). Start-up and relief rebuilds are ignored.
- **Off-screen.** In overlay mode the canvas is cleared and work stops when the slab is more than 200 px off-screen.
- **Context loss.** `webglcontextlost` is prevented. On restore, programs, textures and the relief are re-uploaded.
- **Hidden tab.** No draws.

## 10. Performance

| Item | Budget / measurement |
|---|---|
| Engine bundle | ~17 KB min+gzip (+2.4 KB worker) |
| Relief build | ~220–290 ms in the worker (not on the main thread); rebuilt only on text, size, font or relief-option changes |
| Main-thread measuring | a few ms per rebuild |
| Idle (no pointer, paused video) | 0 draws |
| Video playing, slab on screen | one draw per video frame (25–30/s) |
| Pixel cost | proportional to slab area × resolution². A 920×560 slab at 1.5× is ≈1.2 M shaded pixels per draw (not yet measured on real GPUs; see the caveat below) |

Tuning, if a device struggles:

- **Resolution.** Keep `quality: "auto"`. The resolution drops by itself.
- **Expensive features.** Use `dispersion: 0`, `bubbles: 0` and `antialias: false`, in that order of impact.
- **Smaller slab.** Reduce `thickness` and slab size. The ray march runs longer through thick glass.
- **Phones.** Consider `view: "sway"` or `"still"` with `restTilt` tuned, and offer `enableDeviceTilt()` behind a tap.
- **Very low-end devices.** Ship a `renderStill()` PNG as the poster (§11) and skip the engine with `if (navigator.hardwareConcurrency <= 2) ...`.

**Measurement caveat.** All measurements in this project were made in headless Chromium with SwiftShader (software rendering, no GPU), so absolute fps numbers here are pessimistic. Measure on real devices (§13).

## 11. Accessibility, SEO and fallbacks

**Text and buttons stay real DOM.**

- Carved text is real text with transparent colour, so it is selectable (the selection highlight is styled) and indexed.
- Buttons and links keep native focus, click and keyboard behaviour. The focus ring is a white 2 px outline (`glass.css`). Keyboard focus also lifts the glass button, and Enter/Space presses it.
- The canvas is `aria-hidden` and `pointer-events: none`.

**Reduced motion.** With `prefers-reduced-motion`, the view is still and the demo animation pauses. Your own video is your responsibility: pause it there too.

**No WebGL2.** The host gets `data-glass="off"`, and `glass.css` shows a frosted card with dark ink. For a richer fallback:

1. Export a still from the lab ("Still image" button) or with `renderStill({ scale: 2 })`.
2. Use it as the background image of `[data-glass="off"] .glass-slab`.

**Contrast.** The carved headline is decorative glass. The real text underneath is what assistive tech uses. If you need WCAG contrast for the visible rendering, raise `finish` (matte cuts read darker and more legible) or use `fill: "white"`.

- One low-end laptop with an integrated GPU

**What to check on each:**

- **Mode.** `data-glass="on"`.
- **Alignment.** Carved letters sit exactly under the selectable text. Drag-select the headline to see it.
- **Buttons.** Hover lifts them, press pushes them down, links navigate, Tab shows the focus ring.
- **Edges.** Slab edges are smooth (no stair-steps) once the auto-resolution settles (~3 s).
- **Performance.** Watch `onStats`:
  - `fps` ≥ 50 while moving the pointer;
  - `live: false` when idle with the video paused;
  - `live: false` after scrolling the hero away.
- **Robustness.**
  - Resize the window: re-carve, no drift.
  - Switch EN/LT: re-carve.
  - Background tab and back: resumes.
- **Context loss.** Chrome DevTools console:

  ```js

  const x = gl.getExtension('WEBGL_lose_context');

  The glass returns.
- **iOS.** Device tilt works only after the tap that calls `enableDeviceTilt()`, and only on HTTPS.
- **Reduced motion.** With the OS reduced-motion setting on, the view is still.

```

## 14. Known limitations

- **One slab per engine and per canvas.** Browsers allow roughly 8–16 WebGL contexts per page. For several glass cards, see §16.
- **Two button kinds.** Hover and press state is per kind, not per element.
- **Refraction only sees the background source** (the video). Other page elements behind the slab are not refracted. That is fine for a hero over a full-screen video.
- **Safari.** Safari's WebGL2 is slower on the same hardware. `quality: "auto"` compensates, and the resolution may settle lower.
- **Testing environment.** This was tested only in headless Chromium with software rendering. Real-GPU verification on the target devices (§13) is still to do.
- **Claude artifact viewer.** The viewer sandbox blocks downloads and motion sensors. The lab's "Download PNG" and "phone tilt" work in `carved-glass-lab.html` and on your site.
- **Pages opened from disk** cannot refract your own video (cross-origin rule; see §3). The lab's built-in sea and a file picked with "Your file…" work from disk.

## 15. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Plain frosted card, `data-glass="off"` | No WebGL2 (old browser, GPU blocklisted, context limit) | Expected fallback. Check `chrome://gpu`. |
| Glass is drawn but offset from the HTML | A transform, filter or `contain` on an ancestor, or a slab `transform` set by your CSS | Remove it (§5). |
| Letters carved in the wrong font or spacing | Font not loaded or subset missing | Load the font (latin-ext); `engine.rebuildRelief()` after a class-only change. |
| Glass looks milky or grey everywhere | Edited refraction with the wrong normal sign | `refract(dir, N, 1/ior)` on entry, `refract(dir, -N, ior)` on exit. |
| Background inside the glass is the demo beach | Video tainted (cross-origin) or not ready | CORS (§12); check `onError`. |
| Dashed or stair-stepped slab edges | Resolution stepped down on a slow device | Expected on weak GPUs; `quality: "full"` on desktop; keep `antialias: true`. |
| Glass doesn't follow the pointer on phones | No pointer on touch | `view: "sway"`, or a button calling `enableDeviceTilt()`. |
| Hover lifts both kind-1 buttons | By design | Use one button per kind (§4). |
| Shadow or light band on content below | Overlay draws shadow and caustics around the slab | Lower `caustics`, or give the next section a background. |

## 16. Notes for whoever edits the engine

**Shader edits (`shaders.ts`)**

- Keep CSS-pixel units. `uZTop` and `uZBot` bound the relief search; if you allow taller buttons or deeper cuts, update them in `GlassSlab.draw()`.
- Caustics must stay blurred. Light spreads across the 240 px gap. A crisp Laplacian printed a duplicate of the text on the background in an earlier version.
- Dispersion is applied only where `bounces < .5 && rough < .35`. Elsewhere it is noise and costs time.

**Relief edits (`reliefCore.ts`)**

- It must stay DOM-free, because it runs in the worker. Test it in Node directly: `computeRelief(input)` is synchronous.

**Adding options**

1. Add the field to `GlassOptions` and `DEFAULTS`.
2. If it changes the carving, add it to `RELIEF_KEYS`.
3. Pass it as a uniform in `draw()`.
4. Add a control in `lab/lab.template.html`. A range input with `id` equal to the option name and `data-opt` is bound automatically.

**Multiple glass cards on one page.** Two routes:

- **Simple:** a `GlassSlab` per card. Fine for 2–3 cards; each has its own canvas and context.
- **Scalable:** extend the engine to keep an array of slabs sharing one canvas and context, then loop the slab pass with a scissor per slab.

**Baked fallback for low-power devices:** render stills at build time with Playwright and `renderStill()`.

## 17. Build and tooling

```bash
npm install          # esbuild 0.24, typescript 5.6, react types (dev only)
npm run typecheck    # tsc --noEmit over src, demo, examples, test
npm run build        # dist/ (worker, ESM, IIFE), carved-glass-lab.html, test/overlay.js
```

What the build does:

- `build.mjs` bundles the worker first, because the lab inlines it as a `blob:` worker.
- The lab page is `lab/lab.template.html` with `glass.css` and the bundled `lab/lab.ts` inlined. Edit those two files, never `carved-glass-lab.html`, which is generated.
- `node build.mjs --artifact <file>` additionally writes the lab as a fragment (no doctype/head/body) for publishing as a Claude artifact.
- In your Vite app you don't need any of this. Vite compiles `src/glass/*.ts` and the worker directly.
